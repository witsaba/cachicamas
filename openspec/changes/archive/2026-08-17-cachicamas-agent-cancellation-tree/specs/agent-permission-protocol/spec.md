## MODIFIED Requirements

### R-APP-009 — Cancellation resolves every parked call into a typed abort that names the signal (D7)

When the run's `context.Context` is cancelled while calls are parked, every parked call SHALL be released and SHALL write `Result{Outcome: ExecutionFailure, Failure: <typed abort>}` into its own ordinal slot, carrying its correlation ID, and SHALL emit the matching `tool_end_execution_failure`. Each releasing call MUST deregister its own parked entry so a late wake observes `ErrStrayDecision` rather than closing a channel nothing will read. The rejoin slice returned by `Schedule` MUST be fully populated, and no gate goroutine may wait forever: `runtime.NumGoroutine()` SHALL return to its pre-`Schedule` baseline. Cancellation MUST be honoured on both waits — the acknowledgement wait of `R-APP-002` and the parked wait itself.

**The typed abort's shape changes at AG-14, and only its shape.** Both arms MUST derive the failure from the context's **cancellation cause**, not from the bare context error, so the resulting `*Failure`:

- MUST report `ai.FailureCategoryCancellation` when the cause is one of the harness cancellation sentinels (`R-CAN-001`) — not the `Unavailable` category the pre-AG-14 helper assigns to every error it receives, which made a user interrupt indistinguishable from a provider outage;
- MUST keep the firing sentinel reachable by `errors.Is` through the failure's preserved unwrap chain, so a caller can tell interrupt from shutdown at the call level and not only at the run level;
- MUST keep carrying the call's own correlation ID, unchanged.

**Everything else on this path MUST be unchanged**, and this is a normative constraint, not a description: the parked-set deregistration, the ordinal-slot write, the emitted event kind, the rejoin population and the goroutine-baseline guarantee all stay exactly as they are. In particular, **`D-B`'s two-production-paths contract stays intact**: park release still has exactly the two production paths it has today — an upward-path `WakeParked` and the context-done arms — and AG-14 adds **no third**. The wind-down bound of `R-CAN-006` is not a third path: it is armed only after cancellation and sits inside the call-execution path, never inside the gate (`R-RUN-010` states the same answer from the run driver's side).

A cancellation the *caller* raised on its own context, without going through a harness signal, MUST keep producing the pre-AG-14 typed abort. The category and sentinel changes above apply to the harness signals only.

(Previously: the typed abort was derived from `ctx.Err()` and carried a raw `context.Canceled` under the generic failure category, so an aborted parked call could not name which signal aborted it and read identically to a provider-unavailability failure.)

#### Scenarios

- **S-APP-010** — AG-10.3 two parked calls, one cancel, a fully populated rejoin. Given two calls the policy defers and a run context cancelled while both are parked, when the cancellation fires, then both ordinal slots carry `ExecutionFailure` with a typed `*Failure` derived from the context's cancellation state and their own call IDs, `Schedule` returns rather than hanging, a subsequent `WakeParked` for either ID returns `ErrStrayDecision`, and the goroutine count returns to baseline under `-race`. Verified by `TestPermission_CancellationMidPark_PopulatesRejoinAndNoLeak`, with the acknowledgement-wait arm covered by `TestPermission_AbandonedAckWithCancel_GateDeregistersPromptly`.
- **S-APP-017** — **AG-14: the abort names the signal.** Given a run whose policy defers a call, and a consumer that has read the decision-required event off the run stream, when the harness interrupt signal fires, then that call's ordinal slot carries an execution-failure result whose `*Failure` reports category `Cancellation` and whose unwrap chain satisfies `errors.Is` against the interrupt sentinel and fails it against the shutdown sentinel; and when the same scenario runs with the shutdown signal instead, then the two assertions swap — proving the failure carries the signal's identity rather than a category constant. Cross-referenced to `S-CAN-003`.
- **S-APP-018** — **AG-14 adds no third release path.** Given the AG-14 branch, when the suite runs and `git diff` is taken against the merge base, then `TestPermission_WakeParked_SchedulerReturnsAfterExplicitWake_NoDeadline` (`permission_protocol_test.go:1573-1600`) passes with its source **byte-unchanged**, and every AG-09 and AG-10 scheduler test passes with its source byte-unchanged — a parked call that is neither woken nor cancelled is still not released by anything.

## MODIFIED Explicit non-requirements

The list is reproduced in full; one line is back-annotated as closed and none is removed.

- **Policy content, mode flags, rule sets** — Layer 3 (doc 0004 CO-03). AG-10 ships the protocol only. *(Still open at AG-13: the run driver supplies no policy content either; it forwards whatever policy its caller configured. Still open at AG-14, which adds no policy content.)*
- **Cross-session or cross-run persistence of a remembered rule** (CO-16.1) — the remembered set lives exactly one `Schedule` call. *(Still open. AG-13 does not widen it: a harness-driven run makes N `Schedule` calls, one per tool-calling turn, and a rule remembered in one is not carried into the next. Cross-turn memory is not claimed by any milestone yet. AG-14 does not widen it either — the only state it lets outlive a run is the terminal shutdown flag of `R-CAN-005`, which holds no remembered rules.)*
- **The upward-path wake wired into `Turn`** — AG-13. `Turn()` deliberately exposes no scheduler handle and no wake surface at AG-10. **CLOSED by AG-13**: the wake is wired here, and the shape matters. `Turn` still **returns** no scheduler and still **exposes** no wake handle; the caller instead **injects** a `*Scheduler` it already owns through the nil-default continuation seam (`R-LSK-001`) and calls `WakeParked` on its own value. A caller that supplies no continuation still cannot reach a scheduler, so AG-10's guarantee is preserved rather than revoked. Owned by `R-RUN-010`.
- **Subagent tool scope** — AG-19.3.
- **The full cancellation tree** — AG-14. AG-10 owns per-call abort on the already-threaded `ctx` only. **CLOSED by AG-14**: the tree ships in the `agent-cancellation-tree` capability (`R-CAN-001`…`008`). What lands *here* is exactly one change — the parked abort's typed value now names the firing signal (this requirement). The gate's structure, its two release paths and its goroutine accounting are untouched, and the deadline signal remains unclaimed by any milestone.
- **Making `Schedule` return against a permanently abandoned `sink`** — a pre-existing AG-09 hazard. AG-10 releases the gate goroutine on cancellation; the dispatcher's `sink <- &stamped` send still requires a reader. *(Still open, and AG-13 depends on it being handled correctly by the caller: the run driver keeps a forwarder relaying each turn's events to the consumer sink while the turn is in flight, so the dispatcher always has a reader. That is a run-driver obligation, `R-RUN-002`, not a change to this hazard. Still open at AG-14: the forwarder is one of the harness-owned tasks `R-CAN-006` requires to exit within the wind-down bound, which is a liveness claim about the forwarder, not a repair of this hazard.)*
