## 1. The cost event family AG-06.2 already built (`backend/agent/src/agent/cost_events.go`, full file read, 287 lines)

Two payload types, both registered, both constructible today — **AG-16 wires emission, it does not add vocabulary**:

- `CostTurn` (`:162-165`) — unexported `label CostLabel; figures CostFigures`. `NewCostTurn(run RunID, turn TurnID, label CostLabel, figures CostFigures) (Event, error)` (`:181-193`). `Scope()` returns `CostScopeTurn`. Kind `EventKindCostTurn`, `PlacementTurn` (`event.go:329-331` registry row), `CardinalityAny` (unset → zero value, no cap).
- `CostSession` (`:227-230`) — identical shape, no `turn` field. `NewCostSession(run RunID, label CostLabel, figures CostFigures) (Event, error)` (`:248-257`). `Scope()` returns `CostScopeSession`. Kind `EventKindCostSession`, `PlacementRun` (`event.go:333-335`), `CardinalityAny`.
- `CostFigures` (`:137-157`) — **five exported `uint64` fields, exactly**: `InputTokens`, `OutputTokens`, `CacheReadTokens`, `CacheWriteTokens`, `ReasoningTokens`. No pointer, no optional wrapper, no presence flag of any kind — a plain value struct.
- `CostLabel` (`:90-107`) — closed `uint8` enum, exactly two members: `CostLabelEstimate`, `CostLabelFinal`. Zero value is not a member; both constructors reject it (`:172-176`, `:236-241`).
- `CostScope` (`:50-66`) — closed enum, `CostScopeTurn` / `CostScopeSession`, read-only derived accessor, not a constructor input.

**Mechanically pinned, verified by reading `cost_events_test.go:186-235` (S-APE-083)**: a `reflect.TypeOf(agent.CostFigures{})` walk asserts **exactly 5 fields**, **in this exact name order**, **every field `uint64`**, and **no field name containing** `money|amount|price|total|cents|dollar|usd|currency|fee|charge`. AG-16 **cannot** add a sixth field (e.g. a presence bitmask) to `CostFigures` without breaking this pinned test — any fix for the absent-vs-zero requirement (§7 below) must live outside this struct's shape, or the reflection pin itself must be revised as an explicit, signed-off `S-APE-083` amendment (no precedent for that exists yet in this codebase).

## 2. Layer 1's `ai.Usage` — the source AG-16 must read from (`backend/agent/src/ai/usage.go`, full file read, 193 lines)

```go
type TokenCount struct { count int64; present bool }          // usage.go:44-47
func Tokens(n int64) TokenCount                                 // usage.go:53-55, present=true
func (t TokenCount) Count() (int64, bool)                       // usage.go:63-65

type Usage struct {
    Input, Output, CacheRead, CacheWrite, Reasoning TokenCount   // usage.go:111-149
}
```

- Absence **is** the zero value: a zero `Usage{}` is a fully valid record with all five counts absent (`usage.go:16-19`). `TokenCount.Count()` returns `(0, false)` for absent, `(n, true)` for reported — including `Tokens(0)`, a "reported nought" distinguishable from absence (`usage.go:51-55`).
- Field mapping to `CostFigures` is exact and already documented as intentional in both files: `Input↔InputTokens`, `Output↔OutputTokens` (inclusive of reasoning per `usage.go:124-134`), `CacheRead↔CacheReadTokens`, `CacheWrite↔CacheWriteTokens`, `Reasoning↔ReasoningTokens`.
- **`ai.Usage` is exposed through exactly one event type**: `ai.Completion` (`backend/agent/src/ai/completion.go:34-37`, `func (c Completion) Usage() Usage { return c.usage }`, `:92`). Verified by grepping every `.Usage()` accessor call site in `backend/agent/src/ai/**` — the only production accessor is `completion.go:92`; no other event kind carries a `Usage` field or method.
- `Completion` is registered `Cardinality: CardinalityAtMostOne, Terminal: true` (`ai/event.go:167-170`) — **at most one per stream, and nothing may follow it**. There is **no mid-stream, partial, or incremental usage-bearing event kind anywhere in the shipped `ai` package.**

## 3. The run driver seam — where Turn ends and where a cost event would be emitted

`Turn(ctx, provider, system, transcript, opts, sink) (ai.Message, ai.FinishReason, error)` (`loop.go:248-255`) **does not return `ai.Usage`** — its signature has exactly those three results, unchanged since AG-07.

Inside `Turn`, `turnAccumulator.translate` (`loop.go:832-995`) handles `ai.EventKindCompletion` at `:923-927`:
```go
case ai.EventKindCompletion:
    completion, _ := ev.Completion()
    t.finish = completion.FinishReason()
    t.finishOk = true
    return true
```
**`completion.Usage()` is never called.** The `turnAccumulator` struct (`loop.go:768-810`) has no `usage` field. `finalize()` (`loop.go:1001-1025`) emits `turn_end` (`NewTurnEnd`, no usage argument in its signature) and, on the nil (non-continuation) path, `run_end` — **this is the natural per-turn seam**: `finalize()` is called from exactly two sites (`loop.go:383`, `finishContinuationTurn` at `loop.go:525`), both immediately after `translate` observed a Completion, both already holding the turn's finished state before emitting `turn_end`. A `cost_turn` event, if emitted here, would need `t.usage ai.Usage` added to the accumulator and populated at `:923-927`.

At the run-driver level, `Harness.Run` (`harness.go:353-626`) drives the attempt loop (`:502-570`) and the outer per-logical-turn loop (`:451-619`). `msg, finish, terr = Turn(...)` (`:520`) — **usage is unreachable from `Harness.Run` today**, because `Turn` never returns it. Two structurally different seams exist for cumulative aggregation, and design must choose between them:
  (a) **Widen `Turn`'s return signature** to `(ai.Message, ai.Usage, ai.FinishReason, error)` (or a wrapping struct) so `Harness.Run` can read and accumulate usage per attempt directly. This is a breaking signature change to a function the package doc (`loop.go:11-13`) explicitly designed to stay stable ("a function form ... so AG-13's later Harness can wrap it without changing the signature (D1a)") — a real tension to flag.
  (b) **Have `Turn`/`turnAccumulator.finalize()` emit `cost_turn` directly onto `sink`**, and have `Harness.Run`'s existing per-attempt forwarder goroutine (`for ev := range turnSink { sink <- ev }`, `harness.go:507-509`) intercept each forwarded event, read `ev.CostTurn()` when present, and accumulate into a run-scoped running total — no `Turn` signature change, reuses the existing single-writer forwarding path. This is the option that best matches "cost emission in the run driver from Layer 1 usage" (the milestone's own Deliverable wording) without touching the frozen `Turn(...)` contract.
Cumulative (`cost_session`) state would then live as a new field on `Harness` (nil/zero-default, mirroring the `RetryAttempts`/`RetryTiming`/`Failover` idiom at `harness.go:71-91`) or as a local accumulator inside `Run`'s own stack frame — a local is sufficient since `Harness` is value-form and re-used serially per `R-CAN-002`, and nothing else on `Harness` currently carries cross-run state.

The run's success terminal (`NewRunEnd(runID, RunOutcomeCompleted, nil)`, `harness.go:621-624`) is the natural site for a final `cost_session(Final, ...)` emission, immediately before it — mirroring how `run_end` itself is the run's own terminal marker.

## 4. Retry (AG-15) — CONFIRMED: no usage plumbing exists for a retried attempt, and this is explicitly AG-16's to solve

Read `openspec/specs/agent-retry-failover/spec.md` in full (263 lines) and `harness.go:502-570`, `retry_policy.go:111-126`:

- Each attempt of a retried logical turn gets **its own `turnSink`/forwarder goroutine and its own `Turn` invocation** (`harness.go:502-521`), producing its own `turn_start`/`turn_end` pair with a fresh `TurnID`, all on one contiguous lane inside one run bracket (confirmed by `agent-retry-failover/spec.md:74`, `R-RTY-002`). Structurally, nothing prevents emitting a `cost_turn` (PlacementTurn, CardinalityAny) event per attempt, including a failed one — **if** usage data existed for that attempt.
- **It does not.** `retryDecision` (`retry_policy.go:111-126`) only ever retries (`verdictRetry`, G4) when `errors.As(terr, &failure)` succeeds **and** `failure.PartialOutput() == false` (G3 blocks retry the instant any output was emitted). `ai.Failure` (`provider_failure.go:320-330`, full struct read) has fields `category, retryable, retryAfter, rawLabel, statusClass, requestID, cause, delivery, partialOutput` — **no `usage` field, none at all**. A retryable failure, by definition (G3), never emitted output, but Layer 1's `*ai.Failure` still carries zero information about whether the provider consumed any input tokens before failing — that fact is architecturally invisible to Layer 2 today.
- **The AG-15 spec itself explicitly defers this**, twice, in writing: `agent-retry-failover/spec.md:219` ("Cost accounting for retried attempts | **AG-16**, parallel") and `agent-run-driver/spec.md:326` ("Cost aggregation across turns | **AG-16**"), with no "CLOSED by AG-16" annotation yet (this change is what closes it). AG-15's own proposal.md repeats the identical deferral row (`proposal.md:53`). This is not an oversight AG-16 discovers — it is a load-bearing, pre-recorded handoff.

**Interpretive risk (flag for `sdd-propose`/`sdd-design`, do not resolve here):** the charter's "a retried attempt's tokens are real spend and must be counted" (`0003:1535`, `:1550-1552`) is ambiguous between two readings given the substrate above:
  1. **A literally-failed attempt's own token spend** must be captured and summed — currently **unbuildable**: no source of usage exists on any failure path (`ai.Failure` carries none), and every retryable failure by G3's own gate never emitted output, so it is unclear whether any real provider would even report usage for such an attempt.
  2. **The successful attempt of a logical turn that needed one or more retries** must still contribute its real (non-zero) tokens to the cumulative sum — i.e., the risk being guarded against is a naive accumulator that only sums "turns that succeeded on the first `Turn` call" and silently drops or zeroes a turn that took 2+ attempts. This reading is **fully buildable** with today's substrate: `Completion.Usage()` on the attempt that actually succeeded is real data: reading (b) requires no Layer 1 change and matches every other constraint found in this exploration.
  Reading 2 is the only one consistent with `ai.Failure`'s shape and with AG-15's explicit non-ownership of this problem. `sdd-design` must pick explicitly and record the choice — do not let a scenario's prose imply reading 1 is buildable without re-verifying against `ai.Failure`'s field list above.

## 5. The estimate/final protocol — CONFIRMED structural gap between AG-06.2's own doc comments and the shipped Layer 1 event vocabulary

`cost_events.go:96-103` documents `CostLabelEstimate`/`CostLabelFinal` as: "the label for a figure emitted before the stream's **final usage update**" vs "on the stream's final update." This text is inherited verbatim from doc 0001 § 7 G10 (read in full, `docs/architecture/0001-cachicamas-agent-stack-v2.md:719-732`): *"on models with adaptive reasoning, the reasoning token count only arrives on the **final streamed usage update**, so any mid-stream cost figure is structurally an estimate."*

This describes a **wire-level** phenomenon (a provider's SSE stream may carry more than one usage-bearing chunk, with reasoning tokens completing only on the last one). **Confirmed by direct inspection (§2 above): that multi-chunk detail is fully absorbed by Layer 1's decoder before it ever reaches Layer 2.** `ai.Completion` is the sole, singular, terminal usage carrier per stream — there is no earlier, partial usage-bearing event kind Layer 2 can observe. Therefore:

- A `cost_turn` event emitted at `turnAccumulator.finalize()` (the only point per-turn usage is ever known) **always** already holds the true, complete `Completion.Usage()` — there is no substrate-supported way to emit an earlier, genuinely partial per-turn figure. Per-turn cost events would, with today's plumbing, always be `CostLabelFinal` in practice, never `CostLabelEstimate` — **contradicting AG-16.1 Scenario 3's Given clause** ("usage arriving only on the final stream update ... any earlier figure was labelled estimate") taken at per-turn/single-stream granularity.
- The only substrate-buildable reading of "estimate vs. final" is at a **different axis than one stream's own usage arrival**: e.g., a `cost_session` (cumulative, `PlacementRun`, `CardinalityAny`) event emitted after each intermediate turn as a running total is legitimately `CostLabelEstimate` (the run has not yet concluded, more tokens may follow), and the `cost_session` emitted at the run's own terminal (immediately before `run_end`) is legitimately `CostLabelFinal`. This is fully buildable with today's substrate and satisfies the *label semantics* even though it reinterprets "stream" as "run" rather than "one provider connection."
- **`sdd-design` must resolve this explicitly** — either by finding a Layer 1 mechanism this exploration missed (re-verify `ai.Completion` is truly the only Usage-bearing kind before trusting this conclusion further), or by documenting the reinterpretation above as the actual estimate/final axis AG-16 implements, with an explicit rebuttal of doc 0001 § 7 G10's wire-level framing for why it does not apply as literally written at Layer 2.

## 6. Test substrate (AG-07 `agenttest`) — how usage is scripted

`Script.Steps []Step`, each built via `Emit(ev ai.Event)` (`agenttest/fake_script.go:30-35`) — a script is a flat ordered list of pre-constructed `ai.Event` values, including `ai.NewCompletion(finishReason, usage)`. Verified: a test can script **any** `ai.Usage` value directly, including `ai.Usage{}` (fully absent) or a mixed record (e.g. `ai.Usage{Input: ai.Tokens(100)}` with the rest absent) — `ai.NewCompletion` (`completion.go:63-69`) validates only non-negativity, never requires any field present (`usage.go:151-169`).

`agenttest.Provider` (`fake_provider.go`, full file read, 212 lines) — `NewProvider(scripts ...Script)` (`:64-66`) queues **one Script per `Stream` call**, consumed in order (`consume`, `:138-150`). A retried logical turn therefore needs **N scripts queued**, one per attempt — but per the retry spec's own **Fixture constraint** (`agent-retry-failover/spec.md:36`, verified verbatim): `agenttest.Provider.Stream` can only fail pre-stream in three built-in situations (zero request, cancelled context, script exhaustion) — **a `Script` cannot express an arbitrary retryable pre-stream failure**. Every existing AG-15 retry test uses a **test-local provider wrapper** (the `errorProvider` precedent, `loop_test.go:1408-1421`) that fails its first N calls directly, then delegates to an inner `agenttest.Provider`. AG-16's own retry-adjacent tests (scenario 2, "cumulative counts every attempt") will need the **same wrapper pattern**, not a bare `agenttest.Provider` — `agenttest` itself is not widened by AG-15 and there is no signal AG-16 should widen it either.

No scripting mechanism exists for "usage arriving only on the final stream update" beyond scripting a single `ai.Completion` event with a full `Usage` value at the end of a script's steps — consistent with §5's finding that no intermediate usage-bearing event exists to script in the first place.

## 7. The absent-vs-zero requirement — CONFIRMED structural conflict with `CostFigures`' pinned shape

Milestone acceptance (`0003:1535`) and Scenario 1 (`0003:1544-1547`, read verbatim): *"its cost event carries the turn's five token figures labelled final, honoring absent-vs-zero — absence is reported as absence, never invented zeros."*

`CostFigures` is five plain `uint64` fields (§1) — **structurally incapable of distinguishing "0 reported" from "not reported at all."** Converting `Completion.Usage()` (an `ai.Usage`, which — via `TokenCount`'s presence bit — **can** express absence) into `CostFigures` (which **cannot**) is a lossy operation that discards exactly the distinction this scenario requires, no matter how the conversion function is written. This is the single sharpest, most concrete gap in the whole milestone. Candidate resolutions, none decided here:
  1. **Skip emitting `cost_turn` entirely** when a turn's `Usage` is fully absent (all five `TokenCount`s unreported) — "absence is reported as absence" via the event's non-existence rather than its content. Tension: the scenario says "its cost event carries..." implying an event **is** still emitted.
  2. **Widen `CostLabel`'s closed vocabulary** with a third member (e.g. `CostLabelAbsent`) alongside a documented, explicit "release" of `cost_events.go`/`event.go`'s cost rows — there is codebase precedent for this exact mechanic: AG-14 added a `RunOutcomeShutdown` member "under the recorded `R-LSK-004` release" (per `agent-run-driver/spec.md:325` and `harness.go`/`run_events.go` history). `cost_events.go` and `event.go` are **not** in AG-06's byte-unchanged substrate list (`agent-protocol-events/spec.md:118`, `NFR-APE-004` — that list names only `event_descriptor.go`, `stream_check.go`, `failure.go`, `sequence.go`, build files), so this widening is structurally permitted, unlike an edit to `CostFigures` itself (which **is** mechanically pinned by the `S-APE-083` reflection test).
  3. **Emit `CostFigures{}` (all zero)** and rely on a **separate, new boolean or discriminator** on the event/payload (not on `CostFigures` itself, to respect the reflection pin) to carry "usage was absent" — e.g. widening `CostTurn`/`CostSession` with an unexported `usageAbsent bool` plus a new accessor, leaving `CostFigures`'s own five-field shape untouched. This keeps `S-APE-083` green (it only inspects `CostFigures`, not `CostTurn`/`CostSession`) while adding a new accessor surface.
  `sdd-design` must choose one of these (or another) explicitly and verify it against `cost_events_test.go`'s exact reflection assertions (`:186-235`) before implementation.
