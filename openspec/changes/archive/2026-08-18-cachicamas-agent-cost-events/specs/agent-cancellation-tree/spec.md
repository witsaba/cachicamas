> ## ⚠ THIS DELTA CONTAINS AN AMENDMENT TO AN ENUMERATED ORDER — READ THIS BEFORE THE BLOCKS BELOW
>
> **`R-CAN-002` states the wind-down as a closed, ordered list**: "Wind-down MUST be, **in order**: synthesize orphans over the transcript; close the turn; emit the run-close event through the existing public run-event constructor; return an error matching the firing signal's sentinel" (`spec.md:65`). **`R-CAN-005` inherits that list verbatim** — shutdown "MUST perform the **same** wind-down as an interrupt (`R-CAN-002`), differing in exactly two observable ways" (`spec.md:98`).
>
> AG-16 inserts a `cost_session` carrying `CostLabelFinal` **immediately before** the run-close on the wind-down path, because tokens spent before a cancellation are real spend (`R-CST-006`). That **alters the enumerated order**, and the alteration is therefore an **amendment, signed off here**, not an emission that rides in unrecorded. The new step is inserted into both requirements' lists explicitly; the relative order of every pre-existing step is preserved exactly, and the run-close remains the bracket's last event.
>
> **What this delta does NOT do**, stated so no reader infers a relaxation: it does not weaken the nil-`*Failure` rule on the run-close, does not change either signal's run-outcome member, does not add cancellation vocabulary, does not add an `EventKind`, does not touch `R-CAN-001`'s sentinels or `R-CAN-004`'s idempotence, and does not alter the post-shutdown refusal — which continues to emit **no event whatsoever**, cost events included, and is stated below as an explicit carve-out rather than left to be inferred from silence.
>
> **`S-CAN-001`, `S-CAN-004` and `S-CAN-005` stay green without amendment**, for reasons that are mechanisms rather than reassurances: `CheckStream` accepts a `PlacementRun` event emitted inside an open run bracket (`stream_check.go:157-163`), so the new event is legally placed; those scenarios assert the run-close's outcome, its nil failure and that `run_end` is **last**, all of which remain true when an event precedes it; and `S-CAN-004`'s same-stream equality compares two streams that **both** now carry the cost event, so the comparison is unaffected. Any test that nonetheless requires an edit is an enumerated, signed-off amendment recorded in `apply-progress.md` (`NFR-CST-005`), never a quiet fix.
>
> **Ownership**: which cost events exist, what they carry, and on which closes they are owed is owned by [`../agent-cost-events/spec.md`](../agent-cost-events/spec.md) (`R-CST-005`, `R-CST-006`). This delta owns only what the cancellation wind-down's own enumerated order must now say.

## MODIFIED Requirements

### R-CAN-002 — An interrupt ends the run, not the harness value

An interrupt MUST wind the run down and MUST NOT end the harness value. The run MUST terminate with the **interrupted** run outcome and, per `RunEnd.validate`'s failure-iff-`Failed` rule (`run_events.go:156-161`), with **no** `*Failure` attached. It MUST NOT terminate as failed and MUST NOT carry `ai.FailureCategoryUnavailable`.

Wind-down MUST be, in order: synthesize orphans over the transcript; close the turn; **emit the run-scoped final cost figure**; emit the run-close event through the existing public run-event constructor; return an error matching the firing signal's sentinel. Orphan synthesis is idempotent (`R-HIS-008`), so a turn whose results were already committed synthesizes nothing and the ordering is safe on every path.

**The third step is AG-16's insertion, and it is stated as an amendment rather than absorbed silently.** Before returning, and **immediately before** the run-close, the wind-down MUST emit a `cost_session` carrying `CostLabelFinal` with the run's cumulative token figures at close time (`R-CST-005`, `R-CST-006`). The reason is not symmetry: tokens spent before a cancellation are **real spend**, and a cancelled run that reports nothing is indistinguishable at the consumer from a run that spent nothing. Four constraints bound the insertion:

- **Position is fixed.** It goes after the turn is closed — the turn bracket must already be closed, per the paragraph below — and immediately before the run-close, which remains the run bracket's **last** event. `cost_session` is `PlacementRun` (`event.go:332-334`), so the position is validator-legal, and `CheckStream` MUST accept the recorded wind-down stream **unmodified** with `stream_check.go` **byte-unchanged**.
- **It is best-effort.** If the payload cannot be constructed, the emission is skipped and the wind-down proceeds unchanged: the same run outcome, the same nil `*Failure`, the same returned error, the same sentinel. A cost emission MUST NOT convert an interrupted run into a failed one and MUST NOT attach a `*Failure` to a close that carries none.
- **It writes no transcript.** The emission is a stream event only; it appends nothing, synthesizes nothing, and does not re-run or re-order orphan synthesis.
- **It does not fire where no run bracket exists.** The post-shutdown refusal of `R-CAN-005` MUST continue to emit **no event whatsoever**, cost events explicitly included.

**The turn bracket MUST close before the run bracket does.** `CheckStream` rejects a run-close emitted while a turn bracket is still open, so the turn that observed the cancellation MUST emit its own turn-close first, carrying the **aborted** turn outcome and a `*Failure` of the pre-existing category `ai.FailureCategoryCancellation` — mirroring the mid-stream-fatal branch's existing precedent rather than introducing a path of its own. No new `TurnOutcome` member is introduced: `turn_events.go` stays byte-unchanged (`S-LSK-018`). This is the **turn's** bracket only and does not weaken the rule above: the **run's** close still carries no `*Failure`. Recorded here because the two brackets carry deliberately different failure shapes, and a reader who assumes the run's nil-failure rule also governs the turn's close would read the emitted stream as malformed. **A cancelled turn closes aborted, so it emits no `cost_turn` at all** (`R-CST-001`, `R-LSK-001`'s AG-16 amendment); the run-scoped figure this requirement inserts carries the spend of the turns that closed **before** the signal, and no figure is invented for the aborted one.

After an interrupted run has returned, a subsequent `Run` on the **same harness value** MUST be accepted and MUST be able to complete normally, with the steering queue reopened at `Run` entry (`R-RUN-001` delta). This is the only cross-run behavior this change introduces beyond the terminal shutdown flag of `R-CAN-005`; cross-run transcript state remains AG-21's. **The cumulative cost figure is run-scoped and MUST NOT survive the run**: a second run on the same harness value starts from nothing, because the harness value is serially reused and carries no cross-run state (`R-CST-004`).

(Previously: the wind-down's enumerated order was "synthesize orphans; close the turn; emit the run-close event; return", with no cost emission anywhere on the path — so a cancelled run reported no token spend at all and was, at the consumer, indistinguishable from a run that spent none.)

#### Scenarios

- **S-CAN-002** — **Charter AG-14.1, scenario 1, second Then.** Given a harness value whose first run ended through an interrupt as in `S-CAN-001`, when a second `Run` is driven on that same value against a fresh script, then the second run emits its own complete run bracket, ends with the completed run outcome, returns a nil error, accepts a `Steer` call with a nil return during that second run, and `CheckStream` accepts the second run's stream unmodified. *(AG-16 note: the second run's own final cost figure reflects **only** the second run's turns; no figure from the interrupted first run carries over — see `S-CAN-012`.)*
- **S-CAN-011** — **(bite)** RED-first. Given a scratch tree in which the harness's cause-aware routing is reverted so every non-nil `Turn` error again reaches the unconditional failure path (`harness.go:200-207`), when `S-CAN-001` and `S-CAN-005` run, then both FAIL reporting the failed run outcome and a non-nil failure of category `Unavailable` — proving the cancellation carve-out of the `R-RUN-011` delta is what produces the typed outcome. RED-recorded BEFORE those scenarios are GREEN, then reverted.
- **S-CAN-012** — **AG-16 the wind-down's amended order, and the run-scope of the figure.** Given a run interrupted after at least one turn has already reported usage, when the wind-down completes and the stream is recorded, then the consumer observes the interrupted turn's aborted turn-close carrying **no** `cost_turn`, then a `cost_session` carrying `CostLabelFinal` whose figures equal the cumulative over the `cost_turn` events observed **on that same stream**, then the run-close carrying the interrupted run outcome with a **nil** `*Failure` as its last event, then the sink close, in that order; the returned error still matches the interrupt sentinel; the transcript is exactly what orphan synthesis and the turn close left it, with nothing appended by the cost emission; `CheckStream` accepts the stream unmodified with `stream_check.go` byte-unchanged; and when a second `Run` is then driven on the same harness value, then its own final figure counts only its own turns. Cross-referenced to `R-CST-006` / `S-CST-013`.

### R-CAN-005 — Shutdown winds down identically and then terminally refuses new prompts

Shutdown MUST perform the same wind-down as an interrupt (`R-CAN-002`), differing in exactly two observable ways: the run-end event MUST carry the **shutdown** run outcome (`R-CAN-007`), and the returned error MUST satisfy `errors.Is` against the shutdown sentinel and MUST NOT satisfy it against the interrupt sentinel.

**"The same wind-down" includes AG-16's inserted step, and the inheritance is stated rather than left to be inferred.** A shutdown wind-down MUST likewise emit the `cost_session` carrying `CostLabelFinal` immediately before its run-close, under the identical four constraints `R-CAN-002` states — fixed position, best-effort, no transcript write, and no emission where no run bracket exists. The two signals stay distinguishable by exactly the two observables named above; the cost figure is **not** a third discriminator and MUST NOT differ in shape between the two paths.

Shutdown MUST additionally latch a **terminal, one-way** refusal flag on the harness value. A `Run` invoked after shutdown MUST return the typed post-shutdown refusal (`R-CAN-001`), MUST emit no event whatsoever, and MUST leave the consumer sink in a state the caller can drain to completion. **"No event whatsoever" is absolute and now explicitly includes cost events**: the refusal opens no run bracket, so it emits no `cost_session`, no `cost_turn`, and nothing else. The flag MUST never resume a run and MUST hold no transcript: it is per-value terminal bookkeeping and does not pre-empt AG-21's cross-run state (`agent-run-driver`'s `R-RUN-001`, its one-run-at-a-time clause).

The two signals MUST stay distinguishable **through both nouns of `0003:1379`** — the run-end outcome on the stream and the Go error chain — so a consumer that reads only the stream, such as a Layer 3 TUI holding no Go error, can still tell them apart.

(Previously: the requirement inherited a wind-down whose enumerated order carried no cost emission, and its "no event whatsoever" clause named no event class explicitly — so a reader could not tell whether a post-shutdown refusal was expected to report a zero cost figure or nothing at all.)

#### Scenarios

- **S-CAN-005** — **Charter AG-14.2.** Given a run in flight with the same shape `S-CAN-001` uses, when the shutdown signal fires, then the wind-down produces the same synthesized-origin closures and the same nil-failure run-close shape, the run-end outcome value is the shutdown member and is different from both the interrupted and the failed members, the returned error satisfies `errors.Is` against the shutdown sentinel and fails it against the interrupt sentinel; and when a second `Run` is then invoked on that same harness value, then it returns the typed post-shutdown refusal, that error satisfies `errors.Is` against the shutdown sentinel, the consumer observes no event at all, and `CheckStream` accepts the first run's stream unmodified. *(AG-16 note: "the same … run-close shape" now includes the inherited `cost_session(Final)` immediately preceding the run-close, and "no event at all" on the post-shutdown path includes cost events — both asserted by `S-CAN-013`, which exists so this scenario's implementing test needs no edit.)*
- **S-CAN-013** — **AG-16 shutdown inherits the amended order, and the refusal stays silent.** Given a run shut down after at least one turn has reported usage, when the stream is recorded, then a `cost_session` carrying `CostLabelFinal` appears immediately before the run-close; the run-close carries the **shutdown** run outcome with a nil `*Failure` and is the bracket's last event; the emitted cost figure has the same shape as the interrupted run's in `S-CAN-012` and is **not** a discriminator between the two signals; and when a `Run` is invoked on that harness value after the flag has latched, then the consumer drains the sink to completion having observed **no event of any kind**, cost events included. Cross-referenced to `R-CST-006` / `S-CST-013`.
