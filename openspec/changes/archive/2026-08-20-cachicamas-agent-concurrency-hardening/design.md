# Design: AG-21 — Harden concurrency, backpressure and leaks

> **Change**: `cachicamas-agent-concurrency-hardening` · Phase: `sdd-design` · Store: hybrid
> Subject: **test architecture** (D1: no production code anticipated; fix-in-place contingency pre-authorized).
> Proposal decisions D-A, D-B, D1–D5 are binding; nothing here overturns any of them. Every `file:line` below was opened in this worktree during this phase.
> Size note: this document deliberately exceeds the phase skill's 800-word default because the launch brief mandates settled per-cell drive plans (A–H); tables keep it as short as that mandate allows.

## Technical Approach

Compose the twelve state × signal cells, the two pressure scenarios, and the cross-run scenario entirely from existing `agenttest` primitives (`Gate` `fake_gate.go:28-51`, `Script`/`Step` with only `Emit`/`Hold` `fake_script.go:30-41`, `Provider` request capture `fake_provider.go:157-161`) plus existing `package agent_test` local fixtures — no `agenttest` widening, no new `Step` shape (D5). Cell logic lives in **plain driver functions**, not in test bodies, so the same drivers serve (1) twelve parallel table-driven subtests with a shared, unweakenable assertion core, and (2) the single non-parallel leak-sweep wrapper of D-B, which needs callable scenarios rather than subtests. Synchronization is exclusively `Gate.Reached()`/`Release()`, channel reads, and channel closes — no clock anywhere (`NFR-HKS-002`, `agent-hook-taxonomy/spec.md:318`; `NFR-CAN-002`, `agent-cancellation-tree/spec.md:186`). The one legitimate clock is the wind-down bound, `defaultWindDownBound = 100 * time.Millisecond` (`cancellation.go:92`, doc `:86-91`), injected small per test via `Scheduler.WindDownBound` (`tool.go:243-256`) exactly as `smallWindDownBound = 20ms` already does (`cancellation_winddown_test.go:23`) — a ceiling, never a synchronization point.

## Architecture Decisions

### AD-1 (brief A) — Matrix shape: table-driven subtests over shared plain-function drivers

**Choice**: one file `combined_matrix_test.go` with a `cellCase` table (12 rows: `state`, `signal`, per-row `arrange`/`fire` closures) driven through one shared `runCombinedCell(tb, label, cellCase)` core that owns the invariant assertions. Subtests run as `t.Run(state+"/"+signal, ...)` with `t.Parallel()`.
**Alternatives rejected**: (a) 12 named functions — 12 copies of the assertion core is exactly the surface Risk 2 (silently weakened assertions) needs; (b) pure data table with no closures — the arrangements are structurally different per state (a permission park is not a held provider stream), so a closed data vocabulary would either grow a mini-DSL or lie.
**Rationale against real constraints**:
- *Leak-sweep interaction*: the sweep needs plain callables; `t.Run` bodies are not reusable, driver functions are. Top-level `t.Parallel()` tests are suspended until the serial pass completes, so the non-parallel sweep never overlaps a parallel cell — the same isolation the existing serial leak test already relies on among 1,912 parallel siblings (`cancellation_winddown_test.go:158-196`).
- *Failure legibility*: the subtest name IS the cell (`go test` prints `TestCombinedMatrix/steering_queued/interrupt`); inside the sweep, every `t.Errorf` in the driver is prefixed with the `label` argument, so a sweep-phase failure also names its cell.
- *`-race`*: each cell owns a fresh `Harness`, provider, sink and gates; nothing is shared between parallel cells.
- *Budget*: the shared core is written once (~80–120 lines) instead of twelve times.

Signals: **interrupt** = `h.Interrupt()` after the pending-point read (`cancellation_interrupt_test.go:81-82`); **shutdown** = `h.Shutdown()` (`cancellation_shutdown_test.go:70`); **provider failure** = a scripted terminal `ai.MidStreamFailure` + `ai.ErrorEvent` step (`turn_failure_test.go:32-61`), which is an `Emit`, so *where it can fire is bounded by which provider stream is live at the pending point* — stated per cell below rather than papered over.

*Race-between-arrangement-and-signal audit (the false-green vector named in the brief)*: every "pending" proof above is a happens-before edge the production code itself provides — a `Reached()` close, a synchronous nil `Steer` return, or an event read off the sink — never an inference from elapsed time or from goroutine scheduling. No cell fires a signal that is not strictly ordered after such an edge.
*Charter deviation, disposed at the orchestrator level and recorded here so `sdd-verify` and the archive report inherit it rather than re-litigate it*: the compaction×failure and child-harness-active×failure cells carry the adjusted Then above because it is the ONLY reading consistent with shipped requirements — `R-CMP-010`/`R-CMP-013` (a compaction failure is stream-visible and never interrupts the run) and `Schedule`'s own return shape (`loop.go:542`: `[]Result` and no error at all, so a contained tool-execution failure inside the child can never surface as a Turn-level error on the parent). Changing either behavior is outside AG-21's charter ("correctness under pressure only", `0003:1973`). **Suspension×failure is uniform, not adjusted**: the park only bounds *when* the failure can fire (`S-CNH-005`), never the outcome, which stays `RunOutcomeFailed` plus a typed `*Failure` at that terminal — recorded here (sdd-verify round-2, MAJOR-2) after an earlier draft of this deviation named suspension instead of child-harness-active. `sdd-spec` MUST encode the two genuine exceptions with the adjusted, evidence-cited Then, not the uniform one.
*Overlap disclosure*: cells suspension×interrupt and suspension×shutdown overlap existing S-CAN-003/S-APP-017 tests (`cancellation_shutdown_test.go:30` head comment); AG-21's cells add the uniform full-stream + history assertion core those tests do not carry, and are new tests, not edits.
*Risk-3 fence*: every cell drives exactly ONE `Run` at a time; signals fire from the test goroutine, which is `R-CAN-004`'s already-decided shape, never a second concurrent `Run` (`agent-run-driver/spec.md:87`, `agent-cancellation-tree/spec.md:204`).

### AD-3 (brief C) — Assertion core: existing validators, exact call shapes

Per cell, `runCombinedCell` asserts, in order:
1. **Run returned** — a receive on the cell's `resultCh` (the `cancellation_interrupt_test.go:70-85` shape); never a wall clock.
2. **Contract-ordered events** — `agent.CheckStream(events)` over the full `drainSink(t, sink)` slice (`stream_check.go:92`, `loop_test.go:155`); `report.Violation()` must be nil, stream **unmodified** (the `cancellation_winddown_test.go:138-140` call shape). CheckStream already owns contiguity, bracket closure, and nothing-after-terminal, so no new ordering validator is written.
3. **Valid history, no open call** — walk `hist.Entries()` (`history.go:407`; existing walk shape `cancellation_interrupt_test.go:393`) with one new test-local helper `requireHistoryPaired(tb, hist)`: every assistant `ToolCall` part has a matching result entry (real or `R-HIS-007`-synthesized), and no turn is left open (`CloseTurn` semantics, `history.go:300`). This is the change's ONE new assertion helper; it lives in `package agent_test`, not `agenttest` (D5).
4. **Outcome and error match the firing signal** — last event is `run_end`; outcome `RunOutcomeInterrupted`/`RunOutcomeShutdown` with `errors.Is(err, agent.ErrInterrupted/ErrShutdown)` and cross-sentinel exclusion (`cancellation_interrupt_test.go:87-95`); provider-failure cells: `RunOutcomeFailed` + typed `*Failure` on the R-RUN-011 path (`harness.go:381-397`), except compaction×failure and child-harness-active×failure, whose Then is AD-2's (suspension×failure keeps the uniform outcome — only its timing is bounded by the park, `S-CNH-005`).
5. **Child cells only** — `validateStreamsSeparately` + subagent-bracket kind fence (`nested_run_test.go:48-77`).

### AD-4 (brief D) — Stalled-consumer harness (AG-21.2)

**Stall without a clock**: the sink is **unbuffered** (`make(chan *agent.Event)`); the consumer goroutine reads exactly k events, then blocks on a test-owned `resume` channel. The producer is then genuinely blocked at `sendStamped`'s unconditional send (`harness.go:284-287`) — the harness-facing boundary is lossless *by construction*, which is `R-AGE-006`'s posture (`agent-event-delivery/spec.md:94`). "Stalled" is structural (no receiver), not temporal.
**Scenario 1 (loses nothing)**: no signal fires. Close `resume`; the consumer drains to completion; the run completes. Assert: `CheckStream` valid; every fact committed to `hist.Entries()` has its describing event present (the `R-AGE-006` committed-fact rule, D-Q4) — completeness is checked against the scripted event identity set (count + kinds + call IDs), so a single missing committed-fact event is divergence. **Sanctioned-vs-unsanctioned**: `R-AGE-005`'s sanctioned loss lives at the *loop-internal* boundary and fires only on cancellation with a saturated buffer (`agent-event-delivery/spec.md:84`; mechanism `fake_provider.go:192-210`). Scenario 1 cancels nothing, so the sanctioned path is unreachable and the only admissible observation is **zero loss** — any absence is unsanctioned and fails.
**Scenario 2 (cancellation unblocks within the bound)**: consumer reads until `tool_start` of a cancellation-deaf `BlockingScriptedTool` (`scripted_tool_test.go:75`) via `readUntilToolStart` (`cancellation_winddown_test.go:34`), then stalls; `h.Interrupt()`; consumer resumes draining; **"within the documented bound" is asserted by the run RETURNING, observed by a read on the run's completion channel — never a wall-clock assertion** (`S-CAN-006`'s normative precedent, `agent-cancellation-tree/spec.md:154`). The bound is injected small (`Scheduler{WindDownBound: smallWindDownBound}`, `cancellation_winddown_test.go:165`); the detached call is reported typed — `tool_end_execution_failure`, category Cancellation, `errors.As`-extractable `*agent.DetachedCallError` naming tool and call ID (`cancellation.go:71-84`; assertion shape `cancellation_winddown_test.go:110-136`). That the *bound* (not another mechanism) is what ends the run is proven by bite (e) below, the S-CAN-012 shape (`agent-cancellation-tree/spec.md:155`).

### AD-5 (brief E) — Leak sweep: one non-parallel wrapper, NFR-HKS-005-compliant by construction

**Choice**: `TestConcurrencyHardening_PackageLeakSweep` in `combined_leak_sweep_test.go`, **no `t.Parallel()`** (normative: `S-CAN-006`, `agent-cancellation-tree/spec.md:154`; mechanical: `tb.Setenv` panic, `stream_kit_leak.go:107-110`). Body: `agenttest.RequireNoGoroutineLeak(t, scenario)` where `scenario` calls, serially, the 12 cell drivers + both pressure drivers + the cross-run driver — exactly and only what this change adds (D-B; excluding AG-20's deliberately-gated observer tests, whose caller-owned leak `NFR-HKS-005` bans from any baseline: `agent-hook-taxonomy/spec.md:321`, inheritance named at `:265`).
**NFR-HKS-005 compliance, cited as binding**: (1) no cell driver ever samples `runtime.NumGoroutine()` — the only sampler is `RequireNoGoroutineLeak` itself; (2) every `Gate` a driver constructs is released **inline** before the driver returns (each iteration fully quiesces: drain sink, receive run result, release every gate, close every tool-release channel), and additionally carries a `t.Cleanup(gate.Release)` registered at construction so no abort path leaves a gate held; (3) the permanently-stalled-observer leak is not exercised here at all — it is AG-20's, by design (`agent-run-driver` cite in proposal D5), and the sweep's scenario set structurally excludes it.
**Detached-tool report accounted, not leaked**: the scenario includes the pressure-2 driver, whose iteration releases its deaf tool **after** the run returned — alive past the bound proven by the typed report, exit proven by the release — the verbatim `S-CAN-006` discipline (`cancellation_winddown_test.go:146-157`, `:189-192`), now over a combined cell.
**Cost, with numbers**: `RequireNoGoroutineLeak` runs its scenario 50× (`stream_kit_leak.go:61`) + one 50ms settle (`:77`), tolerance 25 (`:68`). Per iteration: ~15 drivers, all gate-bounded (~1–5ms each) except the two bound-paying drivers (pressure-2 and, if composed with a deaf tool, one matrix cell) at 20ms each → ≈100–200ms/iteration → **≈5–10s total**, small against the ~170s suite. **Recorded fallback** (decided now, not discovered in `sdd-apply`): if the measured sweep exceeds 60s, split into three non-parallel wrappers (one per leaf U1/U2/U3) — still D-B-shaped, still `NFR-HKS-005`-compliant; never widen the tolerance and never drop the accounting cell.

### AD-6 (brief F) — Cross-run scenario: an absence assertion with a minted needle, plus a defeat test

The claim (D2, verbatim): the only state that outlives a run is caller-owned or spec-enumerated; the harness itself retains nothing. Both branches of `harness.go:418-421` are driven; run 1 is always adversarial (interrupted mid-turn with a genuinely open call, the `cancellation_interrupt_test.go:49-84` arrangement), so `windDownRun` really writes `SynthesizeOrphans()`/`CloseTurn()` (`harness.go:352-354`).
- **Nil-`History` branch (the absence half)**: run 1 seeds a **uniquely minted artifact** — a tool-call ID/text nonce minted per test run, never a shape match (this repo's ghost-assertion lesson) — and is interrupted. Run 2 on the same value, still nil `History`. Assert **absence**: the marker appears **nowhere** in run 2's captured provider request (`Provider.Requests()`, `fake_provider.go:157-161`) — and anti-ghost, assert the marker IS present in run 1's own history read-back first, proving the needle is findable at all.
- **Shared-`History` branch**: caller sets `h.History`; after adversarial run 1, assert `hist` contains the synthesized orphan result (R-HIS-007) and run 2's captured request **does** contain it (the legitimate carry, orchestrator disposition Q3). Inventory assertions ride the same test: `sessionStarted` — a `SessionStart` observing hook fires exactly once across both runs (`harness.go:480-483`); `cancelRun` cleared — an `Interrupt()` issued *between* runs is a no-op and run 2 still completes (`harness.go:498-503`); queue — `Steer` after run 1 returns is rejected typed, and reopens for run 2 (`harness.go:468-470`, `:515`); `shutdown` stays false on the interrupt path (`harness.go:457-461`).
- **Defeat test (bite d)**: run the nil-branch absence assertion against a deliberately shared `History` — the marker then DOES reach run 2's request, and the assertion MUST go RED. This defeats the fresh-per-run mechanism at its observable output; a presence-phrased scenario (the `S-RUN-003`/`S-CAN-002` failure shape, `agent-run-driver/spec.md:95`, `agent-cancellation-tree/spec.md:88`) would stay green under exactly this defeat, which is the point.
