## Decision (33.2.2)

RED was GREEN. Skipped 33.2.3 — no production change forced.

The producer's read loop (`stream.go:369–530`) is NOT directly
ctx-aware (it does not select on `ctx.Done()` inside the loop), but
the HTTP/1.1 transport in Go 1.26 tears down the connection when the
caller's context is cancelled, so `Body.Read` returns with a
ctx-tagged error within `DefaultDrainTimeout + 1s`. The producer then
walks its `ctx.Err() != nil` branch (`stream.go:503–526`) and exits
through the unique `defer close(out)` (`stream.go:344`) and the
existing `defer resp.Body.Close()` (`stream.go:345`).

Both design options (A: `Body.Close()` watcher goroutine on
`ctx.Done()`; B: ctx-aware wrapper around `resp.Body`) are
**unnecessary** — the existing defer chain handles the cancellation
path correctly under the empirical harness. R-ATS-003's single-producer
model is preserved; no persistent second goroutine is introduced. The
`RequireNoGoroutineLeak` × 50 repeats confirm the leak posture across
the scenario.

Doc 0002 is **not** amended — no `[decision]` shape was forced, no
R-ATS-003 change, no leak arithmetic shift.

## Deviations from design

1. **Helper name**: design.md / tasks.md name `newDripHandler(2, stallInterval)` (`timeout_test.go:20`) as the fixture, but `newDripHandler` writes plain text rather than SSE frames, so it does not produce an event the consumer can observe before stalling. The file inlines `ai33StallHandler` (a small SSE-parameterized variant) instead. Explore § 5.5 already notes a single-purpose helper is the readable form here; not a refactor of the existing plain-text drip handler. Behavior identical to the design intent.

2. **Forecast vs actual line count**: tasks.md forecast ~200 lines; actual 390 lines (+190). The additional lines are inline helper bodies (`ai33StallHandler`, `ai33FirstEvent`, `ai33DrainUntilClosed`) and a fuller S-3 handler that counts requests on the server side. All test-only; under the 400-line PR review budget.
